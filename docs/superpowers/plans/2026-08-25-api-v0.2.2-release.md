# API v0.2.2 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Version and publish the already-merged post-`api-v0.2.1` backend fixes as the exact `api-v0.2.2` OpenAPI Artifact without changing application behavior or GitOps Desired State.

**Architecture:** `control_plane.app.__version__` remains the only version source and the deterministic exporter regenerates `openapi.json`. The release branch changes only version assertions, the version source, the generated Artifact, and this plan; PR CI proves the candidate before merge, main CI proves the exact release commit, and tag CI creates the GitHub Release.

**Tech Stack:** Python 3.12, FastAPI OpenAPI export, pytest, Ruff, mypy, import-linter, GitHub Actions, GitHub Releases.

**Spec:** `AGENTS.md` sections “OpenAPI Artifact 发布” and “提交与 Pull Request 规范”; `.github/workflows/ci.yml` tag/version equality and Release contract.

## Global Constraints

- Target version and annotated tag are exactly `0.2.2` and `api-v0.2.2`.
- `api-v0.2.1..4aaf721fa91abd729b33765e4e329b02aa2ece02` is the fixed already-merged behavior input; this release task adds no feature, route, DTO, migration, security declaration, or GitOps change.
- Before tagging, the candidate must be merged to `main`, exact-SHA main CI must pass, and local/remote `main` must agree.
- The Release must contain `openapi.json` and `openapi.json.sha256`; downloaded bytes must match the committed Artifact digest.
- Do not modify `docs/superpowers/progress/current.md` without the literal user command `【同步进度】`.

**Files:**
- Modify: `tests/test_version.py`
- Modify: `tests/test_e2e_access_governance.py`

**Interfaces:**
- Consumes: `control_plane.app.__version__` and `bootstrap.create_app().openapi()`.
- Produces: failing assertions that require the application and OpenAPI version to be exactly `0.2.2`.

- [ ] **Step 1: Change the two release assertions to 0.2.2**

Rename `test_release_version_is_0_2_1` to `test_release_version_is_0_2_2` and change both expected strings to `0.2.2`.

- [ ] **Step 2: Run the version tests and record RED**

Run:

```powershell
python -B -m pytest -p no:cacheprovider tests/test_version.py tests/test_e2e_access_governance.py::test_release_version_is_0_2_2 -q
```

Expected: both assertions fail because the current source version is still `0.2.1`.

- [ ] **Step 4: Run the version tests GREEN and compute SHA-256**

```powershell
python -B -m pytest -p no:cacheprovider tests/test_version.py tests/test_e2e_access_governance.py::test_release_version_is_0_2_2 tests/test_openapi_export.py -q

```

Expected: all selected tests pass and one lowercase 64-character digest is recorded.
