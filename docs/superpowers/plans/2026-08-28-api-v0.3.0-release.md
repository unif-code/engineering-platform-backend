# API v0.3.0 Release Implementation Plan

> **Execution gate:** This document prepares the release path only. Merge, tag, GitHub Release, branch cleanup, GitOps mutation, and target-environment smoke testing require a new explicit user approval.

**Goal:** Publish the reviewed V0.3 Requirement and Source Control Foundation contract as the exact `api-v0.3.0` OpenAPI Artifact after the implementation candidate is merged and proven on `main`.

**Architecture:** `control_plane.app.__version__` remains the only version source. The checked-in `openapi.json` is generated only by `scripts/export_openapi.py`. Pull-request CI proves the candidate, `main` CI proves the exact merge commit and publishes its immutable image, and tag CI publishes the OpenAPI Artifact plus SHA-256 sidecar. These are separate from GitOps deployment and environment acceptance.

**Tech Stack:** Python 3.12+, FastAPI, PostgreSQL 18, pytest, Ruff, mypy, import-linter, GitHub Actions, GitHub Releases.

## Fixed release contract

- Version: `0.3.0`; annotated tag: `api-v0.3.0`.
- Candidate scope is the V0.3 browser-facing Requirement foundation, authorized repository query, automatic assignment guard, Source Control worker/connector composition, reconciliation behavior, and controlled repository initialization tool already reviewed in this branch.
- Public API must expose only the V0.3 Requirement create/list/detail routes and authorized repository choice route. Webhooks remain connector-only; later Requirement baseline/delivery APIs remain dormant.
- Real GitLab credentials, GitOps Desired State changes, and target-environment smoke tests are intentionally outside this code candidate.
- Do not update `docs/superpowers/progress/current.md` without the literal user command `【同步进度】`.

## Task 1: Freeze the candidate bytes

- [ ] Set version assertions and the single version source to `0.3.0`.
- [ ] Regenerate `openapi.json` only with `uv run python scripts/export_openapi.py`.
- [ ] Run `uv run python scripts/export_openapi.py --check` and record the lowercase SHA-256 of `openapi.json`.
- [ ] Review the semantic OpenAPI diff: only intended V0.3 routes and DTOs may change; no webhook, worker, secret reference, or future Requirement delivery surface may leak into the public schema.

## Task 2: Prove the implementation candidate

- [ ] Run `uv run ruff format --check .`, `uv run ruff check .`, `uv run mypy .`, and `uv run lint-imports`.
- [ ] Run `uv run alembic upgrade heads` against the integration PostgreSQL database.
- [ ] Run the complete `uv run pytest -v` suite with integration tests required.
- [ ] Run `git diff --check`, inspect the exact diff, and confirm no credentials, local secret values, generated caches, or unrelated user changes are present.
- [ ] Record the exact candidate SHA only after a reviewable commit exists; passing local tests alone is not release approval.

## Task 3: Deliver through Pull Request and exact-main CI

- [ ] After explicit approval, push the isolated branch and open a PR describing behavior changes, security boundaries, migrations/configuration impact, and exact validation commands.
- [ ] Require the PR `verify` job to pass for the exact PR head before merge.
- [ ] After explicit merge approval, merge with the repository's linear-history method and synchronize local `main` with remote `main`.
- [ ] Require both `verify` and `publish-image` to pass for that exact `main` SHA. Record the immutable `ghcr.io/unif-code/engineering-platform-backend@sha256:...` digest; do not treat image publication as deployment acceptance.

## Task 4: Tag and verify the OpenAPI Release

- [ ] After a separate explicit tag/release approval, create annotated tag `api-v0.3.0` at the exact green `main` SHA and push only that tag.
- [ ] Require tag `verify` and `release` jobs to pass, including equality of tag `api-v0.3.0` and application version `0.3.0`.
- [ ] Download `openapi.json` and `openapi.json.sha256` from the GitHub Release into a temporary directory.
- [ ] Verify the sidecar, downloaded Artifact, and committed `openapi.json` have the same SHA-256; verify `info.version == 0.3.0`.
- [ ] Hand the verified release URL and digest to the frontend lock/update task. The frontend must not lock to an unpublished local candidate as if it were a released Artifact.

## Task 5: Keep deployment acceptance separate

- [ ] GitOps may consume only the immutable image digest from the exact green `main` run and only after an explicit deployment approval.
- [ ] Run migration, API health, browser flow, worker/connector, reconciliation, and real GitLab smoke checks in the target environment when credentials and GitOps wiring are ready.
- [ ] Report code candidate, CI, Artifact Release, GitOps rollout, and environment acceptance as separate states. V0.3 is not fully released until every required state is proven.
